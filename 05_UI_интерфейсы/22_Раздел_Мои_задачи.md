# 22. Раздел «Мои задачи» (меню РАБОТА)

Персональная рабочая очередь по ВСЕМ проектам: задачи всех этапов
(проектирование, снабжение, согласование, оплата, работы, документы,
доставки), где сотрудник ответственный, + свободные новые, которые можно
взять в работу. Одно место «что требует моих действий» — без обхода
разделов по проектам.

## Экран (база 05/21)
Сверху вниз, edge-to-edge:
1. **Сводные карточки** (кликабельные — клик ставит срез+фильтр):
   «В работе у меня N» · «Новые доступные M» · «Приостановлено K» ·
   «Выполнено за неделю» (CompletedAt ≥ сегодня−7 дн).
2. **PanelHeader «Мои задачи»** + срезы SegmentToggle:
   - **Мои** — я ответственный, статусы Новая/В работе/Приостановлена;
   - **Доступные** — новые без ответственного (кнопка «Взять в работу»);
   - **Завершённые** — мои Выполнена/Отменена.
3. **Тулбар**: поиск (задача/проект) · селект этапа · селект проекта ·
   группировка SegmentToggle «Списком | По проектам | По этапам»
   (группы — подзаголовки rowSection, этапы в порядке конвейера).
4. **DataTable** (sticky, пагинатор): Задача · Этап (цветной бейдж
   SECTION_META) · Проект · Статус (⏸ причина в тултипе) · Этап-статус
   (словами; supply через supplyStatusLabel) · Позиции N/M · Создана ·
   Срок проекта. У новых в строке — «Взять в работу».
5. **Клик по строке** открывает задачу В КОНТЕКСТЕ проекта:
   openProject → openSection → openTask (паттерн очередей 02Б).

## API
`Subtasks.Query` расширен опциональными фильтрами (01/04 wire):
- `ResponsibleId?: number` — задачи сотрудника (все статусы);
- `FreeOnly?: boolean` — новые без ответственного
  (`responsible_id IS NULL AND status='new'`).
`SubtaskListItem` += `ProjectDeadline` (срок проекта — ориентир, своих
сроков у задач нет).

5Б (сервер): те же линейные шаги SubtasksQuery + два условия WHERE.

UI делает два запроса: `{ResponsibleId: me}` и `{FreeOnly: true}` —
карточки и срезы считаются на клиенте из них.
