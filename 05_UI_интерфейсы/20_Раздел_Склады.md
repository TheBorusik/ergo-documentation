# Раздел «Склады» (левое меню, ДАННЫЕ)

Решение 2026-07-28 (запрос пользователя). Показывает, ЧТО ЛЕЖИТ НА СКЛАДЕ
СЕЙЧАС — сквозной взгляд поверх конвейера позиций (склады уже участвуют в
снабжении: доставка выбирает склад, и в работах: остатки едут на склад).

## Структура
КОНТЕЙНЕР вкладок по навигации 05/11 (как Поставщики/Закупки):
**[Список · pinned] + вкладки открытых складов** (kinds
warehouseList/warehouse, URL /warehouses(/{id}), openWarehouse,
миграция menu-warehouses).

## Семантика «на складе сейчас»
По project_positions.warehouse_id + статусу:
- `delivered` — привезено снабжением, ещё не забрано в работы → «На складе · доставка»
- `to_warehouse` — остатки с работ доставлены → «На складе · остатки»
- `to_warehouse_pending` — задача доставки остатков ещё едет → «В пути на склад»
- mounting/installed — УЖЕ НЕ на складе (забрано в работы/установлено)

Подписи статусов — контекстные (правило «статусы словами по месту»),
локальный Record в WarehousesView (не общий position-status).

## Экраны
- **Список**: таблица складов — Склад · Проект (— общий —) · На складе
  (зелёный бейдж-счётчик) · В пути (жёлтый). Клик — вкладка склада.
- **Вкладка склада**: заголовок с счётчиками «На складе: N · в пути: M»,
  ЕДИНЫЙ фасетный фильтр по номенклатуре (05/19, НОВЫЙ scope=warehouse,
  overlay+закрыт) + таблица: Наименование · Артикул · Кол-во · Статус ·
  Проект · Поставщик.

## API (мок; снятие = удаление из handlers.ts)
- `Warehouses.Query {}` → склады + агрегаты StockCount/InTransitCount +
  ProjectName.
- `WarehousePositions.Query {WarehouseId, CategoryId?, Filters?, Search?}`
  → {WarehouseName, Positions: PositionDetail+ProjectName}; фасеты сужают
  через общий matchNomenclatureIds.
- Фасеты: `Facets.Get {Scope:{Type:"warehouse",Id}}` — ветка в scopeNomIds
  (nomenclature_id позиций склада по статусам выше).
- `Warehouses.GetAll` (простой список для селектов) — как был.
