# База разметки UI (решение 2026-07-28, эталон — hub/VS Code)

Единая структура экранов, чтобы приложение выглядело одинаково и кнопки
не приходилось искать. Три базовых компонента + правила.

## Компоненты (ergo-erp/src/components)

### ui/DataTable — ЕДИНАЯ таблица приложения
- Скроллится ТОЛЬКО ТЕЛО, шапка колонок sticky (не исчезает) — как hub CRUD.
- Колонки конфигом: {key, title, render, width?, align?, sortable?}.
- rowSection — секции-разделители внутри («Переданы дальше — только просмотр»).
- rowStyle — подсветка строк (changedRowStyle и т.п.).
- footer — пагинатор (не скроллится с телом).
- Сортировка по колонкам ЗАЛОЖЕНА в API (sort/onSort) — включим позже.
- Все новые таблицы — только через DataTable; старые переводим волной.

### ui/PanelHeader — хидер панели с действиями
- Высота 35px, заголовок КАПСОМ (как hub SidePanel), под ним — тело.
- ★ ВСЕ действия панели — СВЕРХУ в хидере (правый край), не внизу
  списка: при длинном контенте кнопки не «уезжают», скроллится тело.
- subtitle — счётчики/статус; children — фильтры-переключатели.

### layout/Split, SplitPanel, SplitHandle — resize-панели
- react-resizable-panels: Group id=<экран> (размеры запоминаются),
  Panel (fixed-сторона в px + preserve-pixel-size, контент в %),
  Separator 1px (hover — бренд), hit-area ±3px.
- ★ EDGE-TO-EDGE: линия ручки — зрительный разделитель контента;
  списки/таблицы начинаются ПРЯМО от линии, без пустых padding.
  Отступы остаются только ВНУТРИ форм/деталей (иначе поля слипаются).

## Правила экранов
1. Структура панели: PanelHeader (действия) → тело (flex:1, скролл
   внутри тела — DataTable или форма с overflow:auto).
2. ★ ГЕЙТ ДЕЙСТВИЙ: операции с задачей — ТОЛЬКО у ВЗЯТОЙ В РАБОТУ
   (Status=InProgress). New — подсказка «возьмите задачу в работу»,
   Done/Cancelled — просмотр (значения текстом, без инпутов/кнопок).
3. Шапка задачи (TaskHeader) — всегда сверху с отступом; ниже — панели
   edge-to-edge.

## Где применять Split (анализ 2026-07-28)
СТОИТ: окна с двумя самостоятельными зонами —
- ChangeCompositionModal / PositionSetModal-редактор (каталог | корзина);
- PositionPicker (доступные | выбрано);
- фасетная панель static-режима (панель | результаты) — каталог,
  вкладка склада;
- маппинг цен снабжения (позиции | строки поставщика — при росте);
- мастер-детейл списков разделов при появлении предпросмотра.
НЕ СТОИТ: формы деталей (сделка, элемент, документ — одна колонка со
скроллом), степперы задач, дашборд/обзор (карточки), модалки-подтверждения.

## Пилот
Задача проектирования (DesignTaskContent): PanelHeader «Спецификация»
(Сохранить/Отменить/Изменить состав/Все готовы), DataTable с секцией
заблокированных, гейт по статусу, edge-to-edge. Остальные экраны — волной.
