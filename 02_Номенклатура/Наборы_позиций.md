# Наборы позиций (шаблоны установок)

Решение 2026-07-24 (запрос пользователя). Готовые группы позиций каталога
для быстрого добавления в спецификацию проекта — вместо поштучного выбора.

## Суть
Проектировщик собирает набор один раз (напр. «Приточная секция»: клапан +
воздуховод + отвод + шумоглушитель + решётка одного типоразмера) и потом
добавляет его в спецификацию целиком. У каждой позиции набора — БАЗОВОЕ
кол-во, которое можно поправить после добавления.

Наборы ОБЩИЕ (один каталог на всех) — это просто группировка позиций для
удобства. Проверки совместимости позиций пока НЕТ (продумаем позже).

## Модель
```
position_sets       id · name · description
position_set_items  id · set_id → position_sets
                    element_position_id → element_positions (позиция каталога)
                    quantity (базовое кол-во)
```

## API (мок; снятие = удаление из handlers.ts)
- `PositionSets.Query` → список наборов (Id, Name, Description, ItemsCount).
- `PositionSets.Get {SetId}` → набор с позициями (Name/Article/Quantity).
- `PositionSets.Save {Id, Name, Description, Items[]}` — upsert (Id=0 новый,
  иначе пересоздание строк).
- `PositionSets.Delete {Id}`.

## UI (ред. 2026-07-28: наборы — ВКЛАДКАМИ, решение пользователя)
- Номенклатура — **ОТДЕЛЬНАЯ зона-вкладка «Наборы»** (pinned, рядом с
  Каталог/Элементы/Справочники). Зона — КОНТЕЙНЕР по образцу «Элементов»
  (правило 05/12 §6 «создание сущностей — вкладкой-черновиком»):
  **[Список·pinned] + вкладки наборов** (kinds nomSetList/nomSet, URL
  /nomenclature/sets/{id|new}, openNomSet). Деталь набора — ЧЕРНОВИК:
  dirty-точка на вкладке + SaveGuard + подсветка изменений (changedStyle
  у имени/описания, changedRowStyle у строк состава + «· новая»);
  [Сохранить]/[Отменить] появляются только при изменениях — В ОДНОЙ
  строке с именем/описанием (зона зарезервирована, контент не прыгает —
  отзыв пользователя 2026-07-28); «Новый набор»
  → черновик-вкладка, после Создать — постоянная вкладка сохранённого.
  Конструктор: фасетный выбор (FacetFilter scope=catalog) + корзина с
  кол-вом — на всю рабочую область (модалка PositionSetModal УПРАЗДНЕНА).
  Удаление — из списка, подтверждение модалкой.
- Окно выбора позиций проектировщика (`ChangeCompositionModal`) — две
  вкладки **[Позиции | Наборы]**. «Позиции» — фасетный каталог (панель+
  поиск+фильтр) + корзина. «Наборы» — БЕЗ фасетов/поиска: список наборов
  с ★ РАСКРЫВАЮЩИМСЯ ПРЕДПРОСМОТРОМ (2026-07-28, запрос пользователя):
  клик по набору (шеврон) → таблица его позиций (имя · артикул · базовое
  кол-во; загрузка лениво, кэш per-набор) → «В спецификацию» → позиции
  падают в корзину с базовым кол-вом (дальше правятся как строки черновика).
- Модалка «Новая позиция» (NewPositionModal) ШИРЕ — 980px: элемент
  сверху; ФИКСИРОВАННЫЕ свойства — ОТДЕЛЬНОЙ строкой-плашкой ТЕКСТОМ
  («Тип изделия: Воздуховод 🔒 · Тип сечения: Прямоугольное 🔒 · задано
  элементом») по правилу «нередактируемое не показываем инпутами»
  (4-й отзыв: в общей сетке фиксированные сливались с полями ввода);
  редактируемые — РОВНОЙ СЕТКОЙ одинаковых колонок (grid auto-fill
  minmax(205px,1fr); поля выровнены по столбцам, инпут на ширину колонки,
  подсказка/ошибка ПОД полем), порядок: ОБЯЗАТЕЛЬНЫЕ (*) → необязательные,
  внутри группы по SortOrder. Живой предпросмотр
  имени/артикула — СНИЗУ во всю ширину («функциональная форма, не диалог
  да/нет»). Создание позиций остаётся МОДАЛКОЙ осознанно:
  главный сценарий — из окна проектировщика поверх состава (уводить во
  вкладку = терять контекст задачи); редактирование позиций НЕ делаем
  (позиция разошлась по проектам/снимкам закупок — менять историю нельзя;
  ошибся — создай правильную).
